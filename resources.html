How to Use, Customize, and Verify These Lab Resources

Every archive, YAML file, and cheatsheet on this page is exported directly from our 3-node Proxmox VE 9.2 home lab and daily Obsidian production vaults. Before dropping any template onto a live server or personal workstation, review the quick setup notes below so your paths, permissions, and DNS rules match your own environment.

1. Importing the Obsidian Starter Vault Safely

Never extract the starter vault ZIP directly on top of an existing Obsidian folder, or you risk overwriting your .obsidian plugin settings and custom hotkeys. Instead, unzip obsidian-starter-vault.zip into a brand-new folder (for example, Documents\TechSimpld-Vault), open Obsidian, click Open folder as vault, and select that new directory.

Once opened, Obsidian will prompt you to trust community plugins because the vault ships pre-configured for Dataview and Templater. Review the 90 System folder to inspect the included CSS snippets and template files before turning off Restricted Mode. If you already have a mature vault, copy only the specific templates or Dataview snippets you want into your existing folders, and use our Obsidian Markdown & Frontmatter Formatter to standardize older notes so Dataview queries pick them up cleanly.

2. Customizing the Docker Compose Starter Pack

Each stack inside homelab-docker-compose-pack.zip uses placeholder host paths, timezones, and credentials so nothing sensitive is baked into the YAML. Before running docker compose up -d, inspect every volumes: mapping and update the left-hand host path to match your storage layout (for example, /opt/docker/app-name on Linux or a mounted dataset on TrueNAS).

  • Match Linux file ownership: Run id on your Docker host to confirm your PUID and PGID (usually 1000). Setting these in your .env file stops containers from writing root-owned configuration files.
  • Avoid archived container updaters: The legacy Watchtower repository was archived in December 2025. For new stacks, replace blind auto-updates with Arcane (which adds 48-hour release delays and version locks) and manage standalone hosts with Dockhand.
  • Build custom stacks on the fly: If you only need two or three services with custom ports and a single companion .env file, generate a tailored stack in your browser with the Docker Compose & .env Generator.

3. Applying Pi-hole Blocklists Without Breaking Everyday Apps

Over-aggressive adlists are the number one reason households turn off local DNS filtering. The URLs inside pihole-blocklists.txt focus on telemetry, malware, and smart TV tracking while keeping streaming services, online banking, and mobile push notifications intact.

Add one or two lists at a time under Adlists in Pi-hole (or DNS blocklists in AdGuard Home), run pihole -g to rebuild Gravity, and monitor the Query Log for 24 hours. Keep the whitelist section from the file handy so you can restore broken subdomains quickly, or follow our Pi-hole Smart Blocking & Custom Lists Guide to assign stricter blocklists only to IoT devices while keeping work laptops on a lighter group.

4. Using the Proxmox CLI Cheatsheet & Cloudflare Checklist

The proxmox-cheatsheet.md file is formatted as plain Markdown so you can drop it straight into your Obsidian vault or keep it in /root/ on your primary Proxmox host for quick SSH lookups during maintenance. It covers pct container lifecycle commands, qm VM controls, Ceph health checks (ceph -s), and cluster quorum diagnostics. When planning new containers or checking RAM headroom before a migration, pair it with the Proxmox LXC & VM Resource Sizer and the IPv4 Subnet & VLAN Calculator.

For remote access, walk through cloudflare-zero-trust-checklist.md alongside our Cloudflare Zero Trust Tunnel Guide to confirm that every internal HTTP service is routed over an outbound encrypted tunnel with zero open ports on your home router and an Email or Google OTP Access policy enforced at the edge.
