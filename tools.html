How These Tools Work & Why They Run 100% Client-Side

Home lab documentation routinely contains internal network addresses, VLAN layouts, service names, and configuration paths that should never be uploaded to a third-party web server. Every utility on TechSimpld is written in plain client-side JavaScript with zero external API calls. Once a tool page finishes loading, you can even disconnect from the internet and continue generating Compose files, calculating subnets, or formatting Obsidian notes.

Methodology Behind the Calculators

  • Proxmox Capacity Math: The resource sizer reserves 2.0 GB of physical host RAM for Proxmox VE system daemons and 20 GB of boot storage before computing guest allocation percentages, flagging warnings at 80% memory commitment so ZFS ARC or Ceph OSDs are not starved into OOM events.
  • CIDR & Subnet Calculations: IPv4 parsing uses 32-bit unsigned bitwise operations to compute exact network IDs, broadcast addresses, wildcard masks, and RFC 1918 scope classification, then splits any prefix evenly into smaller VLAN blocks.
  • Weighted 24/7 Power & TCO Modeling: Rather than multiplying peak CPU TDP by 24 hours (which drastically overstates real bills), the power calculator blends idle wattage and active load hours into a true 24-hour weighted average, multiplies by 365 days, and adds upfront hardware cost for a realistic 3-year TCO.
  • Docker Compose & .env Separation: Generated stacks intentionally pull secrets, timezones, and host paths into a companion .env file so your docker-compose.yml stays portable and safe to back up.

Built Directly From Our Physical Lab

Every preset and rule of thumb inside these tools comes from day-to-day testing on our 3-node Dell OptiPlex 9020 Proxmox VE 9.2 HA cluster (96 GB total RAM, Ceph SSD storage, VLAN 100 lab network, and VLAN 200 replication network).
