Formatting Clean Markdown & YAML Properties for Obsidian

I document every IP reservation, VLAN assignment, and Proxmox container spec inside an Obsidian vault synced via self-hosted CouchDB. Keeping tables and YAML frontmatter consistent makes those notes readable in plain-text editors, diff-friendly in Git, and queryable with Obsidian's Properties panel and Dataview plugin.

What Each Formatter Mode Does

  • Markdown Table Formatter: Parses unaligned pipe tables, comma-separated exports (CSV), tab-separated spreadsheet copies (TSV), or semicolon files and outputs evenly padded GitHub-Flavored Markdown tables with left, center, or right column alignment.
  • YAML Frontmatter Properties: Cleans loose key-value pairs (such as title, tags, date, status, and aliases) and wraps them inside valid triple-dash delimiters (---) expected by Obsidian Properties, Hugo, Jekyll, and Astro.
  • Smart Obsidian Note Helper: Fixes heading spacing, normalizes inconsistent bullet markers, trims trailing whitespace, and cleans inline tags so imported web clips or raw drafts match your vault conventions.

Tips for Dataview & Long-Term Vault Hygiene

  • Use lowercase keys in YAML frontmatter: Keys like updated, status, and project are case-sensitive in Dataview. Standardizing them lets queries like TABLE file.mtime AS "Updated", status WHERE type = "homelab" work reliably across hundreds of notes.
  • Keep dates in ISO 8601 format (YYYY-MM-DD): ISO dates sort chronologically as plain text and parse cleanly in Obsidian Daily Notes, Templater, and Dataview without regional month/day ambiguity.
  • Why client-side matters for notes: Personal knowledge bases often hold internal hostnames, network maps, or private journal entries. Every transformation in this formatter runs strictly in browser JavaScript with zero network requests.
