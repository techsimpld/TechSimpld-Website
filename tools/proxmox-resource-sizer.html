Proxmox VE Sizing Rules of Thumb (Tested on a 3-Node OptiPlex 9020 Cluster)

Each node in the TechSimpld lab runs Proxmox VE 9.2 on a refurbished Dell OptiPlex 9020 with an Intel Core i7-4770 (4 cores / 8 threads) and 32 GB of DDR3 RAM, backed by Ceph storage across all three hosts. Because we run High Availability (HA), every node needs enough free RAM and CPU headroom to absorb workloads if another node goes down for maintenance.

LXC Containers vs. Full QEMU VMs

  • Default to unprivileged LXC containers for Linux services: DNS sinks (Pi-hole, AdGuard Home), Uptime Kuma, Gotify, and reverse proxies share the host Linux kernel. They boot in seconds and idle at roughly 30 MB to 80 MB of RAM, letting a single 32 GB node comfortably host a dozen services.
  • Reserve QEMU VMs for kernel isolation or non-Linux OSes: Use full virtual machines for Windows guests, Home Assistant OS, TrueNAS, or Docker hosts where you want strict kernel isolation and painless live migration across cluster nodes.
  • Enable nesting carefully: The generated pct create command includes --unprivileged 1 --features nesting=1 so modern systemd services inside Debian or Ubuntu templates start cleanly without privileged host exposure.

CPU Overcommit & Memory Reserve Guidelines

  • Safe vCPU overcommit (2.5:1 to 3:1): Most home lab containers sit below 5% CPU utilization 95% of the day. Assigning 20 to 24 total vCPUs on an 8-thread host works smoothly as long as you avoid overcommitting heavy databases, video transcoders, or game servers.
  • Never allocate 100% of physical RAM: Proxmox VE itself needs roughly 2 GB for host services, plus memory for Ceph OSDs or ZFS ARC cache. On a 32 GB host, keeping total guest RAM commitments at or below 75% to 80% prevents the Linux OOM killer from silently terminating containers during nightly backups.
  • Leave 20% storage headroom: Thin-provisioned LVM-thin, ZFS, and Ceph pools degrade sharply when they cross 80% utilization. Keep free pool space available for live VM snapshots and Proxmox Backup Server staging.
